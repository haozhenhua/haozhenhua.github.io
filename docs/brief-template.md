# 每日早报模板

供后续定时任务对照。不要编造数字、引语、标题或行情；每一项都要有当次抓取的来源链接，时间换算为 Asia/Shanghai（UTC+8）并标注时区。

## 查重（必做）

写稿前先读 `docs/brief-memory/seen.json` 和近日已发布的早报。已经记录的新闻事件、本地新闻、HN 条目、微博话题、X 帖文或油管视频，不要再写一遍；同一事件换了新的报道链接，也视为已见。只有出现实质性新进展时，才写简短「续报」，并更新该条的 `last_brief`。

金融市场数字和每日天气预报数字每天更新，不算重复新闻，不必写入 `seen.json`；海淀区、昌平区本地新闻按新闻查重，须写入 `seen.json`。金融市场仍须把本期实际采用的读数追加进 `docs/brief-memory/finance-history.json`，用来计算相邻两期早报之间的涨跌。书摘按 `docs/reading-plan-2026-11.md` 分期，也不算重复新闻。同一油管频道的新一集可以写，已经写过的同一条视频不要再写。

发布当天稿件时，把本期内新写进早报的条目追加进 `docs/brief-memory/seen.json`，与文章在同一次提交里推送。字段约定见 `docs/brief-memory/README.md`。

## 文件

- 路径：`_posts/YYYY-MM-DD-daily-brief.md`
- 建议固定 permalink：`/YYYY/MM/DD/daily-brief/`

## Front matter

```yaml
---
layout: post
title: "早报 · YYYY-MM-DD"
date: YYYY-MM-DD HH:MM:SS +0800
category: daily
categories: [daily]
tags: [每日早报, 金融市场, 天气, 本地新闻, 全球头条, Hacker News, X, 微博, 油管访谈, 本月阅读]
collected_at: "YYYY-MM-DD HH:MM:SS Asia/Shanghai (UTC+8)"
permalink: /YYYY/MM/DD/daily-brief/
---
```

若当天是补发或下午编发，在文首说明，不要假装写于 09:00 之前。

## 正文结构（按此顺序）

1. **金融市场**：黄金 XAU/USD；美元兑人民币（准确标注是中间价还是市场化参考汇率）；上证指数 000001；深证成指 399001。列出数值、涨跌、来源链接、采集时间。A 股若仍在交易，写明「盘中」。写稿前读取 `docs/brief-memory/finance-history.json`。黄金与市场化参考汇率等接口通常不提供涨跌，变化栏必须用上一期早报入库的同序列读数计算：本期值减上一期值，再算涨跌幅，并写明「较上一期早报（上一期采集时间，Asia/Shanghai）」。只与同源、同口径的上一期快照比较，不要把中间价和市场化参考汇率混算。若该序列还没有上一期读数，写「本期为档案首笔读数」，不要写「接口未提供涨跌」后留空。人民币中间价若能取到上一发布日官方中间价，变化栏以官方口径为主（并注明上一发布日）；A 股变化栏以官方较昨收为主。定时早报通常在 09:15 中间价和 09:30 开盘之前写成：若当日官方中间价、A 股开盘或收盘等尚未公布，数值栏必须采用最近一次已公布的官方读数来发布，不要留空，也不要只写「尚未公布」。A 股用最近一个交易日的收盘价，并附该日相对其昨收的官方涨跌，标明收盘日期；中间价用上一发布日中间价，并附相对再上一发布日的官方变动，标明发布日期。周末或假期同样沿用最近一个交易日或发布日，不要编造开盘价、当日中间价或尚未发生的涨跌。若写稿时已在盘中，用盘中价并标明「盘中」；若当日官方收盘或中间价已经公布，则用当日官方数字。入库时注明本期采用的是上一交易日收盘还是当日官方读数。发布时把本期快照追加进 `finance-history.json`，与文章同一次提交。
2. **天气与本地新闻**：分两块，先写北京市区天气预报，再按区写海淀区、昌平区本地新闻。抓取方法、可重复的接口和页面见 `docs/weather-and-local-news.md`。天气预报城市为北京市区，优先使用中国气象局城市预报站点 54511（名称「北京」，公开页 `https://weather.cma.cn/web/weather/54511.html`，JSON 接口 `https://weather.cma.cn/api/weather/view?stationid=54511`），不要随便改用郊区或区县站点。温度用摄氏度。若接口提供当前或当日早晨实况，写出气温、天气现象或风力、湿度等实有字段，并标注接口 `lastUpdate` 与本次采集时间（Asia/Shanghai，UTC+8）。再写今日预报和未来 2–3 天展望：高温、低温、天气现象；降水、风力和空气质量只在同一来源确实提供时才写，不要把另一家的 AQI 混进这组预报。引用来源链接。接口失败时换该文档中的备用源，并在文中说明；任何情况下都不要编造温度或天气。本地新闻只收海淀区、昌平区的真正本地报道，按区分列，不要把两条新闻的归属写混。优先区政府网站、区融媒体或当地报纸，以及明确写该区事实的北京主流媒体。全国新闻只是顺便提到区名的不要写，广告不要写。保留原标题并链接原文，用中文做摘要，不转载全文。有材料时每区约 3–5 条，来源较薄就少写，不要堆目录。本地新闻纳入 `docs/brief-memory/seen.json` 查重：已经写过的事件不要再写，除非有实质性新进展（续报）；标识约定见 `docs/brief-memory/README.md`（`local:haidian:` / `local:changping:` 或 `news:` 规范化 URL）。天气预报数字像金融市场一样每日更新，不必写入 `seen.json`。
3. **全球头条**：BBC World、BBC 中文、NYT World、The Guardian World；路透或美联社仅在源实际可用时加入。中文摘要，保留原标题与链接，不整篇转载。
4. **Hacker News 近期文章**：抓取当前首页（Algolia `https://hn.algolia.com/api/v1/search?tags=front_page&hitsPerPage=30` 或官方首页 / hnrss）。对最热或讨论最多的 8–12 篇打开原文（并用 HN 讨论作评论语境），写中文摘要，保留英文标题，同时链接原文与 HN 帖。引语最多一两句，不转载全文。其余首页条目用短列表：英文标题、链接、一行中文、HN 点数与评论数。检查链接时只丢掉真正的 404；401/403/405 仍可列出。时间用 Asia/Shanghai。
5. **X 热门与科技圈**：全球及有关地区趋势，加上 AI/IT 圈讨论。使用已安装的 X 公共连接器工具，不要自造接口。摘要并分析，引用帖子或趋势链接。未核实传言标明「在流传」。明显的假模型名垃圾信息可省略。
6. **微博热搜**：请求 `https://weibo.com/ajax/side/hotSearch`，使用桌面 User-Agent、`Referer: https://weibo.com/`、`Accept: application/json`。区分置顶/政务（hotgov）、自然热搜与广告。科技、AI、IT、国际、重大社会话题写摘要与分析；纯娱乐放进「速览」。链接到 `s.weibo.com` 搜索页。接口失败时在文中说明，不要编造话题。
7. **油管科技访谈**：对照 `docs/youtube-sources.md` 的频道名单与抓取说明。官方订阅源在本机环境中可能不可用，按该说明从频道视频页解析最新节目，再打开视频页取发布时间、时长和官方简介。只要近约 7–10 天、时长约 15 分钟以上的访谈或对谈；跳过短视频、预告和明显不是访谈的内容。依据官方简介、章节目录与出品方说明写中文 brief，保留英文标题、频道、时长、发布时间（Asia/Shanghai）和视频链接。不要编造他们说过的话，不要转载字幕或全文。节目简介中的排名或业绩数字，标明是节目或出品方的说法。每天选四至六条即可。若某期只是复述当天其他栏目已写过的新闻，不要再展开，必要时一行「续报」。
8. **本月阅读与今日书摘**：对照 `docs/reading-plan-2026-11.md`。若当天是计划中的工作日分期，把该日书摘写入早报（可按原文微调衔接，但不要改写得面目全非，也不要编造书中没有的论断或页码）；并附本月四本书与本周进度的简表或链接到 `/reading/`。周末或没有安排的日子，只保留书单和进度指引，不要硬塞新的章节摘要。注明书名、作者与章节；只做精炼，不转载章节正文。
9. **今日总结**：短评当天的信息环境；若有书摘，可点一句阅读进度。也可点一句当天访谈里最值得记住的判断，但不要把总结写成节目复述。

## 文风

- 正文用中文，外文与 HN 标题、油管节目标题保持英文。
- 用 Markdown 链接引用。
- 不编造，不整篇转载受版权保护的文本。
